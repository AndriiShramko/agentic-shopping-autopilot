# Agentic commerce landscape (as of 2026-08-31) and open-source prior art

Who lets an AI shopping agent finish an autonomous checkout and pay today, in which countries, and for whose agent? This page maps the vendor landscape (OpenAI, Google, Visa, Mastercard, PayPal / Perplexity, Amazon, Alibaba, InPost, Allegro, OLX, Stripe) and the open-source prior art as of 2026-08-31, with every claim tagged by evidence level. It explains why a buyer-side autopilot bound by a purchase mandate for Allegro.pl and OLX.pl is still an open niche, and how Agentic Shopping Autopilot positions itself against ACP, UCP, AP2 and the existing GitHub projects.

**Questions this page answers**

- Which AI shopping agents can actually complete an autonomous checkout where the AI agent pays, and in which countries?
- Is there an open-source AI shopping agent that buys on Allegro or OLX in Poland under a purchase mandate?
- What do ACP, UCP, AP2, Visa TAP and Mastercard Agent Pay offer to a user's own agent (Claude Code, Codex) rather than to a vendor's agent?
- What did users praise and complain about in ChatGPT Instant Checkout, Perplexity Comet and InPost Von Halsky?

Related pages: [architecture.md](architecture.md), [mandate-spec.md](mandate-spec.md), [payments.md](payments.md), [marketplaces.md](marketplaces.md), [execution-stack.md](execution-stack.md).

## Part 1. Map of agentic commerce solutions (state on 2026-08-31)

Scope of comparison: an open-source layer where the user's own agent drives a real shop all the way to an autonomous payment inside a purchase mandate. MVP market: Poland (Allegro.pl, OLX.pl).

Evidence legend: **[fact]** = confirmed by a dated source; **[vendor claim]** = vendor statement without independent verification; **[hypothesis]** = researcher's inference. Source URLs are collected in the Sources section at the end of the page.

### 1. OpenAI Instant Checkout + Agentic Commerce Protocol (ACP)

- Launch: Instant Checkout went live on 2025-09-29 as a "Buy" button directly in ChatGPT; ACP was co-developed with Stripe and published as an open specification. [fact] (OpenAI, 2025-09-29; Stripe newsroom)
- Geography: US only, for US ChatGPT users (Free / Plus / Pro) and US Etsy sellers; Shopify merchants were "coming soon". No expansion beyond the US happened before the shutdown. [fact] (TechRadar; Retail Dive, 2025-09-29)
- Shut down: OpenAI wound Instant Checkout down as a product — announced 2026-03-04/05 (Digital Commerce 360, 2026-03-06), fully wound down by 2026-03-24 (CNBC) — because of low conversion (press: only about 8% of US adult users tried it in the first month) and moved to the model "AI does discovery, checkout stays with the merchant" through ChatGPT Apps (see section 10). [fact] (Digital Commerce 360, 2026-03-06; CNBC, 2026-03-24; Webinterpret; Silk Road Nexus)
- The ACP protocol lives on: the specification is maintained by OpenAI and Stripe on GitHub and was extended to product discovery on 2026-03-24. [fact] (GitHub agentic-commerce-protocol; Verity Score)
- Availability to a non-native agent: the protocol is open (any agent could in theory act as the ACP buyer side), but real merchant ACP integrations are US retail and there is no mass acceptance of third-party agents. [fact/hypothesis]
- Poland: nothing for end users except ChatGPT Apps (Allegro, section 10). [fact]

### 2. Google Universal Commerce Protocol (UCP) + Universal Cart

- Launch: UCP was announced by Google at NRF on 2026-01-11, open source (Apache 2.0), co-developed with Shopify plus Etsy, Wayfair, Target and Walmart; 20+ retailers, payment networks and processors on board. Built into Google AI Mode, Gemini and Microsoft Copilot Checkout. [fact] (Shopify Engineering; blog.google; ASK BOSCO)
- Development: 2026-03-19 brought the Cart, Catalog and Identity Linking modules plus onboarding through Merchant Center. [fact] (Passionfruit; Google Merchant Center Help)
- Universal Cart: announced at Google Marketing Live / I/O on 2026-05-19/20 as a cross-retailer cart in Search and Gemini, later YouTube and Gmail; launching "this summer" in the US. [fact] (TechCrunch, 2026-05-19; blog.google)
- Geography: the UCP experience is US; expansion to Canada, Australia and then the UK is announced. Poland and the EU are not named. [fact] (blog.google, Google Marketing Live)
- Availability to a non-native agent: the protocol is open and Microsoft Copilot already transacts through UCP, so a third-party agent can connect, but the merchant side is a US pool only. [fact]

### 3. Google Agent Payments Protocol (AP2)

- Launch: announced on 2025-09-16 with 60+ partners (Mastercard, PayPal, Adyen, Worldpay, Coinbase and others); a "mandates" architecture (Intent Mandate / Cart Mandate / Payment Mandate) of cryptographically signed agent authority. [fact] (Google Cloud Blog; ap2-protocol.org)
- v0.2 (April 2026) added "Human Not Present" payments: autonomous execution under instructions issued in advance. This directly matches the purchase-mandate idea of this project (see [mandate-spec.md](mandate-spec.md)). [fact] (Paz.ai; Eco)
- Donated to the FIDO Alliance in 2026 for neutral governance of the standard. [fact] (blog.google; FIDO Alliance)
- Status for end users: a standard, not a product; live deployments are pilots (PayPal wallet with the Google Conversational Commerce Agent, Mastercard Agent Pay inside PayPal, the x402 crypto extension). In Poland there is nowhere for a user to "enable AP2". [fact]
- Availability to a non-native agent: yes, the specification is open on GitHub and any agent can implement it, but an accepting side (issuer, PSP or merchant) is required. [fact/hypothesis]

### 4. Visa Intelligent Commerce (VIC) / Trusted Agent Protocol (TAP)

- VIC was announced on 2025-04-30; TAP was introduced in October 2025 with 10+ partners (including Cloudflare) as a framework that lets a merchant tell a trusted agent from a malicious bot; available in the Visa Developer Center and on GitHub. [fact] (Visa investor news, 2025-10-14; Visa Developer)
- Status: 100+ partners, 30+ building in the sandbox, 20+ agents integrating directly, and hundreds of controlled real agentic transactions in production. These are pilots / an early phase, not a consumer product. [vendor claim] (Visa, April 2026; usa.visa.com)
- CEMEA region (including Eastern Europe): the "Agentic Ready" program launched on 2026-05-20; phase 1 covers issuer readiness (a test environment), not consumers. [fact] (Visa CEMEA, 2026-05-20)
- Poland: nothing for end users directly; for this project VIC / TAP is a potential layer for legitimizing the agent toward merchants and, post-MVP, a tokenized card with limits (the MVP uses the user's existing saved payment methods, see the project decisions below). [hypothesis]

### 5. Mastercard Agent Pay

- Announced on 2025-04-29 ("Agentic Tokens" on top of tokenization). Pilot with Citi and US Bank in September 2025; full availability for US cardholders in November 2025. Partners: Microsoft, PayPal, Google. [fact] (Mastercard, 2025-04-29; Eco, 2026)
- 2026-06-10: "Agent Pay for Machines" (agent-to-agent micropayments, machine payers); Agent Suite for enterprises in Q2 2026. [fact] (Mastercard, 2026-06-10; Fortune, 2026-06-10)
- Poland: not available to end users (US issuers); no Polish issuing bank has announced Agent Pay (no mentions found in the 2026-08-31 search). [fact/hypothesis]
- Availability to a non-native agent: Agent Pay is designed as a network of agents registered with Mastercard; a third-party open-source agent could in theory register, but practice so far is enterprise-first. [hypothesis]

### 6. PayPal (Agent Toolkit) x Perplexity Comet

- 2025-09-03: PayPal and Venmo users received early access to the Comet browser plus a free year of Perplexity Pro (US and selected other countries). [fact] (PayPal newsroom, 2025-09-03)
- November 2025: "Instant Buy" / "Buy with Pro", an agentic purchase inside Perplexity paid through PayPal; January 2026: PayPal acquired Cymbio (catalog infrastructure). The press describes Comet plus PayPal as the most active agentic checkout of 2026, ahead of ChatGPT. [fact/vendor claim] (Dataconomy, 2025-11-20; secnews.gr, 2026)
- Comet itself (a browser agent, free since 2025-10-02, Android available) can navigate any site and drive it to checkout. It is the closest analog of this project's idea, but it is closed, tied to Perplexity, runs on PayPal rails and requires human confirmation of the purchase. [fact] (eMarketer review)
- Amazon v. Perplexity: lawsuit in November 2025 (CFAA; Amazon alleged that the agent disguised itself as a Chrome browser and evaded blocks); preliminary injunction in March 2026 (CNBC, 2026-03-10); on 2026-08-04 the Ninth Circuit vacated the injunction, holding that Amazon had not shown a likelihood of success on its CFAA claim against a user-directed agent; the case continues on the merits. An interlocutory but favorable signal for user agents on third-party sites, not a final precedent. [fact] (9th Cir. opinion, 2026-08-04; Engadget)
- Poland: the Comet browser downloads and works in Poland; agentic purchases target US merchants and PayPal; "Buy with Pro" does not work for Polish shops (BLIK, Allegro). [fact/hypothesis]

### 7. Amazon "Buy for Me" / Rufus / Alexa+

- "Buy for Me" has been piloted since 2025-04-08: buying from third-party brand sites directly in the Amazon app (Amazon passes encrypted name, address and payment data). Limited beta for a subset of US users, iOS / Android. [fact] (About Amazon; Digital Commerce 360, 2025-04-08)
- March 2026: Buy for Me / Shop Direct opened to merchants (feeds via Feedonomics, Salsify, CEDCommerce); May 2026: "Alexa for Shopping" (Rufus plus Alexa+). [fact] (Digital Commerce 360, 2026-03-11 and 2026-05-13)
- Amazon joined neither ACP nor UCP; it builds a proprietary ecosystem and litigates against a third-party agent (section 6). [fact] (Opascope)
- Poland: Buy for Me is unavailable; Rufus on amazon.pl is not confirmed. Amazon has joined neither ACP nor UCP and has litigated against one third-party agent (Amazon v. Perplexity, section 6); no path for non-native agents is offered. [fact]

### 8. Alibaba / Taobao / Qwen + Alipay AI Pay

- The Qwen App got access to the whole Taobao / Tmall catalog (4+ billion items) with ordering, logistics and after-sales agents; the Qwen Shopping Assistant inside Taobao runs end-to-end from idea to after-sales service. [vendor claim] (Alibaba Group; eMarketer)
- Alipay AI Pay: more than 120 million transactions in one week of February 2026, the largest live agentic-payments service in the world; January 2026: the Agentic Commerce Trust Protocol (Qwen App + Taobao Instant Commerce + Alipay). [fact/vendor claim] (Business Wire via Morningstar, 2026-02-13; Caixin, 2026-03-20)
- Geography: China (Alipay or Chinese payment methods required). Irrelevant for Poland as a product, relevant as proof of demand for autonomous agent payment. [fact]

### 9. InPost "Von Halsky" (Poland)

- Presented by InPost in March 2026: an AI assistant (a dog character) inside the InPost Mobile app with chat and voice, offer search and comparison, review aggregation and purchase without leaving the app; payment by BLIK, card, Google Pay or Apple Pay. Gradual rollout to all ~17 million users from 2026-06-15 (a beta of 100k users before that). Free. [fact] (ISBtech, 03.2026; ITReseller; dobreprogramy)
- Assortment: only the network of connected merchants (over 4,000 companies: x-kom, Komputronik, RTV Euro AGD, Modivo, Sportano; integrations via Shoper and Base / InPost Pay). Allegro and OLX are outside the network; InPost positions itself as their competitor. [fact] (PurePC; Shoper; CrypS)
- Autonomy: an assisted purchase (the user confirms and pays in the app), not an autonomous agent with a mandate. [fact/hypothesis]
- Market reaction: skepticism from some experts, who compared it to an online shop with a search engine of unclear purpose (Spider's Web, 03.2026, op-ed); for shops a "golden cage" risk: the algorithm demands price aggression and the customer bonds with the assistant rather than the shop's brand (Vorma; RaiseYourSales). [fact] A Res Futura report (relayed by Fronda, 07.2026) said it observed patterns consistent with coordinated activity in online discussions about InPost / Von Halsky between 2026-06-21 and 2026-07-20, without attributing them to any party; organic reviews should therefore be read with caution. [report claim, single source] (Fronda relaying Res Futura)

### 10. Allegro x OpenAI and OLX (Poland)

- 2026-05-11: strategic partnership between Allegro and OpenAI (access to technology, influence on OpenAI products). [fact] (Allegro Media, 2026-05-11)
- Around 2026-05-13: the Allegro app in ChatGPT, one of the first Polish apps in the ChatGPT App Store: conversational product selection, product cards (price, photo, rating), login to the Allegro account; the "Kup na Allegro" button takes the user to the order form on Allegro, so payment is not in the chat and finalization happens on Allegro's side. A merchant-side AI assistant launched as well. [fact] (Allegro Media, 05.2026; Cashless; Wiadomości Handlowe; test by android.com.pl)
- OLX Group, April 2026, CLAIM AI conference in Lisbon: AutoGPT (automotive vertical, live for OTOMOTO / Poland as a ChatGPT app, OpenAI partnership, trained on OLX's own deal data), CompassGPT (real estate), AutoIQ (for dealers). These are search-and-advice agents without order placement or payment. The generalist marketplace OLX.pl has no agentic purchase. [fact] (Prosus, 04.2026; Yahoo Finance)
- Important for the niche hypothesis: neither Allegro nor OLX lets any agent, even native ChatGPT, complete payment autonomously, and neither has ACP-checkout or UCP integrations (no mentions found on 2026-08-31). [fact/hypothesis]

### 11. Infrastructure for "your own agent" (rails you can build on)

- Stripe Issuing for agents: virtual cards for agents that are single-use, limited by amount / single merchant / single transaction, with real-time authorization of every charge attempt. This maps closely onto the purchase-mandate concept. [fact] (docs.stripe.com/issuing/agents)
- Stripe Link for agents (2026-04-30): the wallet issues the agent a single-use card or a Shared Payment Token after consumer confirmation; user-set limits and modes where the agent acts without approval are promised. [fact] (TechCrunch, 2026-04-30)
- Open source: only hobby wrappers exist (ShopEZ-AI-Agent: GPT-4o + Browser Use + Playwright for Amazon / Walmart; amz-browser-purchase on AWS AgentCore; awesome-agentic-commerce lists). No product of the class "own agent + mandate wallet + arbitrary shops + Poland / Polish payment methods" was found. [fact, as of the 2026-08-31 search] (ShopEZ-AI-Agent; awesome-agentic-commerce)
- Limitation for Poland: ChatGPT agent mode / Operator is officially unavailable in the EU / EEA (GDPR, DMA, AI Act), so OpenAI's native agentic purchase is closed in Poland for regulatory reasons; signs of quiet enablement on some European accounts appeared, and the status is unstable. [fact/uncertain] (Euronews, 2025-01-24; datastudios.org; help.openai.com)

### User reviews and adoption: what people praise and what they complain about

- Instant Checkout did not take off with users: about 8% tried it in the first month; buyers were keen to learn but not to buy through ChatGPT, and the shutdown itself is the main "review". [fact] (TechRadar; Webinterpret)
- Hacker News discussion of the ACP / Instant Checkout announcement (id 45416080): skepticism about trusting AI with money and about ChatGPT becoming an ad storefront; single-item, no-cart purchasing is a demo, not commerce; technical criticism that shop bot detection cuts headless agents off before checkout and that product data is too dirty for reliable automation. [fact, aggregated from thread summaries] (HN; nekuda substack)
- A first buyer experience with Instant Checkout: the gift search got more confusing the longer it went; it was unclear which Etsy items were eligible at all (Buy vs Visit; only sellers in Offsite Ads). [fact] (Yahoo Tech test)
- Comet (Perplexity): praised as an assistant for navigation and comparison; in an independent purchase test the agent found prices correctly but got confused at checkout in 2 of 3 purchases and could not handle multi-step forms; in the eMarketer test it repeatedly hit errors on the checkout page. [fact] (AI Tool Analysis; eMarketer)
- Comet security ("Scamlexity", Guardio Labs, 08.2025): the agent bought an item in a fake shop without human confirmation, autofilled card and address, clicked phishing links and fell for prompt injection through hidden text / CAPTCHA. This is the main argument for why full autonomy needs mandate limits rather than a raw card. [fact] (BleepingComputer; HackMag)
- Geo complaints: everything live is US-first (Instant Checkout, Universal Cart, Agent Pay, Buy for Me); in the EU / Poland OpenAI's agent mode is closed by regulation, so users outside the US are systematically excluded from the "lucky ones" the headlines describe. [fact] (TechRadar; Euronews)
- Von Halsky (Poland): positives are fast routine purchases in two clicks inside one app; criticism covers the narrow partner-only assortment, unclear purpose, the "golden cage" for merchants and beta roughness; the coordinated-activity patterns reported by Res Futura (a single-source report claim, see section 9) leave few clean organic reviews. [fact] (sources in section 9)
- Primary Reddit / X threads with purchase breakdowns were not systematically surveyed for this edition; across secondary aggregators the complaint pattern is uniform: slow, breaks at checkout, CAPTCHA / bot detection, redundant confirmations or, conversely, a frightening absence of confirmations. This pattern should be treated as indicative. [hypothesis based on the sources listed]

### Niches: what is closed and what remains

Closed by the giants: (a) discovery and recommendations in chat: ChatGPT Apps, Google AI Mode, Qwen, Von Halsky; (b) checkout at ACP / UCP-integrated US merchants: Google, Microsoft, Stripe; (c) US agentic payment rails: Mastercard, Visa, PayPal, Stripe; (d) China as a whole: Alibaba / Alipay; (e) in Poland, assisted purchase inside closed networks: Von Halsky (own network) and Allegro (own app, checkout on its own site).

Test of the hypothesis "the user's own agent + sites without ACP integration + full payment autonomy = an unclaimed niche": confirmed, with three caveats. [hypothesis grounded in the facts above]

No live solution combines all three properties: the giants offer either someone else's agent inside a closed ecosystem (Comet, Von Halsky, Qwen), an open protocol without a consumer product (ACP, UCP, AP2), or US-only payment autonomy (Agent Pay, Link). In Poland nobody offers autonomous agentic payment; Allegro and OLX do not hand checkout even to native agents. AP2 v0.2 "human not present" and Stripe Issuing for agents are ready building blocks for the mandate idea (see the project decisions below for what the MVP actually uses).

1. Technical: the experience of Instant Checkout and the Comet tests shows that the bottleneck is not payment but reliably passing checkout on an arbitrary site (bot detection, CAPTCHA, multi-step forms); Guardio, eMarketer and HN agree on this. See [anti-bot-policy.md](anti-bot-policy.md) and [execution-stack.md](execution-stack.md).
2. Legal / payments: the Ninth Circuit decision of 2026-08-04 (Amazon v. Perplexity) is an interlocutory tailwind for agents on third-party sites, but the case is not over; in the EU, PSD2 / SCA applies to card payments (SCA is required for electronic card payments unless an exemption applies: low-value, transaction risk analysis, trusted beneficiary; the issuer always has the final word and may challenge any payment, see [payments.md](payments.md), section 2.1; the real challenge rate at small amounts is therefore an empirical question and the project's first MVP metric, see the project decisions below; the research note suggested virtual cards with pre-authorization and limits or BLIK-like schemes for this [hypothesis], while the project chose a different route, see below) and so does the AI Act (OpenAI has not stated why agent mode is withheld in the EEA; press cites GDPR, DMA and the AI Act) [hypothesis].
3. Timing: the window may be closing: Visa "Agentic Ready" is already in CEMEA and Google promises UCP expansion; the niche is real on a 12–24 month horizon.

### Part 1 conclusion

1. The market has split: protocols are open (ACP, UCP, AP2; any agent can speak them), but all live products are closed and US- or China-centric; OpenAI shut Instant Checkout in 03.2026 after low adoption (press: about 8% trial in the first month); HN and press commentary point to low trust in paying inside a chat as a likely reason. [fact / hypothesis]
2. In Poland the maximum today is assisted selection: the Allegro app in ChatGPT (checkout on Allegro), Von Halsky (a closed network of 4,000 shops, manual confirmation), OLX AutoGPT (search only). Nobody offers autonomous payment under a mandate.
3. The niche hypothesis is confirmed: "own agent + any shops without ACP + autonomous payment within limits" is claimed by nobody, and the building blocks exist (AP2 "human not present", Stripe Issuing for agents / Link, TAP for agent legitimization; the MVP itself uses the user's existing saved payment methods, see below).
4. Main risks: checkout reliability (bot detection / CAPTCHA, exactly where Comet and Instant Checkout broke), PSD2 / SCA and the AI Act in the EU, the unfinished Amazon v. Perplexity case (an interlocutory ruling favorable to user agents as of 2026-08-04, not a final precedent), and a 12–24 month window before UCP and Visa reach Europe.

## How the project reads this landscape (project decisions, 2026-08-31)

These decisions are final for the MVP and override any contrary suggestion in the research above.

- Autonomy means everything except challenges: the agent completes checkout and presses the pay button inside the mandate. A human is involved only for the bank's own 3DS / SMS challenge (PSD2 / SCA, unavoidable), a CAPTCHA / anti-bot challenge, or any deviation from the mandate. A "human confirms payment" mode exists only as an optional config flag, not as the default. See [mandate-spec.md](mandate-spec.md) and the template [PURCHASE_MANDATE.template.md](../examples/PURCHASE_MANDATE.template.md).
- Payment rails for the MVP are the user's existing payment methods already saved in the marketplace account: a one-click saved card (PayU) and / or Allegro Pay. No new cards or services; virtual or disposable cards (Stripe Issuing, Stripe Link, Revolut-style cards) are mentioned only as alternatives other users may choose. One-time BLIK codes are physically incompatible with autonomy because a human generates the code. Consequently the mandate limit is enforced by the agent plus an append-only audit log, not by a card hard cap. See [payments.md](payments.md).
- The first and most important MVP metric is the field-measured frequency of bank challenges (3DS / SMS) on the saved card / Allegro Pay at small amounts; it determines the real share of purchases with zero human involvement. The agent never splits, times or structures purchases to avoid an SCA challenge; a challenge is always handed to the user (see [payments.md](payments.md), section 2.1).
- Marketplace terms: Allegro's Terms (Regulamin, edition effective 2026-09-01, read 2026-09-03) prohibit the use of bots and other software tools while using Allegro (art. 10.11) and scraping of its data for reuse (art. 10.10), and state that automated solutions are used at the user's own risk (art. 2.8); secondary reports describe this as a ban on automated ordering. An AI agent driving the user's own browser may fall under art. 10.11. Allegro publishes no buyer-side checkout API in its public developer documentation (as of 2026-08-31). The project does not disguise the agent and does not attempt to defeat any platform control; its default completes payment inside the mandate, an optional human-confirm flag exists, and each account holder decides and accepts the risk for their own account. Operating rules: the user's own logged-in Chrome profile, one account, human pace as a load-and-respect rule (see [anti-bot-policy.md](anti-bot-policy.md)). See [marketplaces.md](marketplaces.md).
- The project never bypasses anti-bot, CAPTCHA or 3DS: no fingerprint spoofing, no proxies, no anti-detect browsers, no headless farms. A real user browser profile, human pace and honest agent identification (Web Bot Auth) where accepted. See [anti-bot-policy.md](anti-bot-policy.md).
- OLX in the MVP means only the native escrow flow "Kup z Przesyłką OLX"; there is no chat / negotiation module (that is v2, with human escalation).
- Secrets (card data, cookies, OTP) never enter LLM context, git or logs; they live only in the OS keychain / browser profile, and reports are redacted. See [security.md](security.md).

### Key observations

1. The protocol niche is closed by the giants. Three competing standards: ACP (OpenAI + Stripe, Apache-2.0), AP2 (Google, mandates, Apache-2.0), UCP (the Google + Shopify camp, a hypothesis from the maintainer composition; Apache-2.0). All are alive with commits in August 2026 [fact, GitHub API, 2026-08-31]. There is no need to invent a mandate format: take the Intent / Cart Mandate from AP2.
2. The niche "buyer-side autopilot on top of real shops that have no merchant-side agent integration (no ACP / UCP)" is not closed. Everything is merchant-side (ACP / UCP plugins), compare-only (northcinder), universal browser agents without commerce logic (browser-use, Stagehand), or payment tokens with a US geoblock (stripe/link-cli: US Link accounts only [fact]). End-to-end "found, ordered, paid" in open source was really done only by the archived Fewsats/amazon-mcp (Amazon + L402) [fact].
3. Poland / EU / PSD2: a confirmed gap. A targeted search (2026-08-31) found no project of the kind "agent buys with BLIK / Przelewy24 / PSD2" [fact, web search]. Bricks exist: allegro-open-mcp-server (whole Allegro REST API, MIT), olx-mcp (OLX PL search, MIT; prior art only, not reused in the MVP because its data path is a non-public endpoint), adorsys/open-banking-gateway (PSD2 XS2A, not agentic). EU merchant-side: only the Shopware plugins of agentic-commerce-lab.
4. The niche "mandate + human-in-the-loop" is hot right now: northcinder collected 1,218 stars in two weeks (created 2026-08-17 [fact]), internet-court-skill 5,168 stars in 2.5 months [fact]. This project's differentiator is the same ideology, but with real Polish marketplaces and fiat payment.
5. Risk / urgency: about 10 allegro-mcp servers already exist [fact, search], none with meaningful adoption (0-5 stars). The window to become the canonical Allegro / OLX layer for agents is open, but for months, not years [hypothesis].

### How this project differs from everything found

- Buyer-side, not merchant-side, unlike the ACP / UCP plugins (their READMEs describe shop integration [fact]).
- Real shops that have no merchant-side agent integration (no ACP / UCP): Allegro and OLX have implemented neither ACP nor UCP [hypothesis: no evidence of implementation found].
- Fiat in a PSD2 / SCA context: the user's own payment methods already saved in the marketplace account (see [payments.md](payments.md)), not crypto (x402 / L402) and not US-only cards.
- A purchase mandate issued in advance (like the AP2 Intent Mandate); execution packaged as agent skills, a site skill plus MCP for Claude Code / Codex (like Shopify ucp-cli in form). See [site-skill-spec.md](site-skill-spec.md), [registry.md](registry.md) and the reference skill [../skills/allegro.pl/](../skills/allegro.pl/) (SKILL.md, selectors.yaml, flows/).

### Part 2 conclusion

1. The niche is not closed: a buyer-side autopilot for Allegro.pl / OLX.pl with fiat payment and a mandate is absent from open source [fact as of the 2026-08-31 search]; everything that exists is protocols, merchant plugins, compare-only tools, or US / crypto.
2. Top 3 to reuse: (a) piotrlinski/allegro-open-mcp-server, a ready Allegro API layer, MIT; (b) AP2 (google-agentic-commerce/AP2) for the mandate format; (c) browser-use or Stagehand for checkout execution (see [execution-stack.md](execution-stack.md)). l-margiela/olx-mcp (OLX search including PL, MIT) is prior art, not reused in the MVP, because its data path is a non-public endpoint; the MVP searches OLX in the user's own browser session.
3. Top 3 to watch or join: northcinder (an ideological twin, 1.2k stars in two weeks; PL adapters could be contributed upstream), Shopify/ucp-cli + UCP (the "shopping skill" form and possible future merchant coverage), internet-court-skill + visa/trusted-agent-protocol (where mandates and agent trust are heading).
4. The project's contribution makes sense as an AP2-mandate-compatible buyer-side skill, not as a new protocol.
